# haskell-pkgs Agent Guide

This repository curates the Haskell package set for the ekapkgs poly-repo ecosystem, built on [ekala-project/corepkgs](https://github.com/ekala-project/corepkgs). corepkgs supplies the Haskell infrastructure (GHC compilers, `generic-builder`, `make-package-set`, `haskell.lib`); this repo supplies the package definitions via `config.overlays.haskell`.

## Repository Layout

| Path | Purpose |
|------|---------|
| [`default.nix`](default.nix) | Entry point; imports `pins.nix` and applies `pkgs-module.nix` via the corepkgs module system |
| [`pins.nix`](pins.nix) | Pinned corepkgs revision (must match `flake.lock`) |
| [`pkgs-module.nix`](pkgs-module.nix) | Composes the haskell overlay (`hackage-packages.nix` → `pkgs/` → `haskell-packages.nix`) and the top-level overlays; sets `haskellPackages` to the compiler named in `compiler.nix` |
| [`compiler.nix`](compiler.nix) | Default GHC attribute name (e.g. `"ghc9103Binary"`), shared by `pkgs-module.nix` and the regenerate script |
| [`hackage-packages.nix`](hackage-packages.nix) | **Generated** (~365k lines) by `scripts/regenerate-hackage-packages.sh` (hackage2ekapkgs) |
| [`pkgs/`](pkgs/) | Hand-written Haskell packages, auto-called via `mkAutoCalledPackageDir`; these override same-named entries from `hackage-packages.nix`. Includes the generator itself (`pkgs/hackage2ekapkgs`) |
| [`overrides/`](overrides/) | Per-package fixes, one `<attr>.nix` per package (jailbreaks, `overrideCabal`, version selection, dependency overrides); `_*.nix` are shared helpers. Loaded by [`haskell-packages.nix`](haskell-packages.nix) |
| [`top-level.nix`](top-level.nix) | **Generated** by `scripts/generate-top-level.py`; exposes executables at `pkgs` scope via `justStaticExecutables`, skipping names corepkgs already defines |
| [`configuration-hackage2nix/`](configuration-hackage2nix/) | Generator config: `main.yaml`, `stackage.yaml`, `broken.yaml`, `transitive-broken.yaml`, `system-dependency-paths.yaml`, `compiler.yaml` (generated by `scripts/generate-compiler-config.sh`) |
| [`data/hackage/`](data/hackage/) | all-cabal-hashes snapshot pin (`pin.json`, unpacked hash) |
| [`scripts/`](scripts/) | Regeneration and update scripts |
| [`ci/`](ci/) | Eval, regeneration and build checks |

## Commit Conventions

- **New packages:** `<pkg>: init at <version>`
- **Version updates:** `<pkg>: <old version> -> <new version>`
- **Build fixes:** `<pkg>: <succinct message>` (e.g. `lzma-conduit: doJailbreak for GHC 9.10`)
- **corepkgs pin bumps:** `corepkgs: update pin`
- **Do not** add AI attribution (e.g., `Co-Authored-By`) to commit messages
- **One logical change per commit** — squash small fixups into the commit they belong to rather than creating separate fixup commits

## Where to Make a Change

**Never hand-edit `hackage-packages.nix` or `top-level.nix`** — they are regenerated, and `ci/check-regeneration.sh` fails if regenerating changes them.

| Goal | Where |
|------|-------|
| Relax version bounds, patch sources, add/remove deps, disable tests | `overrides/<attr>.nix`, using `haskellLib` (`haskell.lib.compose`: `doJailbreak`, `overrideCabal`, `dontCheck`, ...) |
| Use a newer version than Hackage/Stackage selects (one-off) | `overrides/<attr>.nix` selecting a generated versioned attribute (see `overrides/hnix-store-core.nix`); the latest Hackage version is generated as `<name>_<version>` whenever the default is pinned lower; other versions need an `extra-packages` entry in `main.yaml` |
| Package not on Hackage, or built from a git source | `pkgs/<name>/default.nix` |
| Change which version hackage2nix generates | `configuration-hackage2nix/main.yaml` (`default-package-overrides`), then regenerate |
| Mark/unmark broken | `configuration-hackage2nix/broken.yaml`, then regenerate |
| System dep name differs in corepkgs, lives in a nested set, or comes from libc/the toolchain | `configuration-hackage2nix/system-dependency-paths.yaml`, then regenerate |
| System dep not yet in corepkgs | Nothing — the package is generated as conditionally broken (see below) |
| Change the default GHC | `compiler.nix`, then `scripts/generate-compiler-config.sh` and regenerate |

An override file looks like this; take everything from the arguments (`prev`, `pkgs`, `haskellLib`, `lib`, `final`) and start with a comment explaining *why* it exists (e.g. the upstream issue or GHC incompatibility):

```nix
# Upper bounds exclude the GHC 9.10 boot libraries.
{ prev, haskellLib, ... }:
haskellLib.doJailbreak prev.lzma-conduit
```

## Writing Packages in `pkgs/`

The directory name becomes the attribute name in `haskellPackages`. Packages use the Haskell `mkDerivation`, not `stdenv.mkDerivation`:

```nix
{
  mkDerivation,
  lib,
  fetchFromGitHub,
  base,
  text,
}:
mkDerivation {
  pname = "<name>";
  version = "<version>";
  src = fetchFromGitHub {
    owner = "...";
    repo = "...";
    rev = "v<version>";
    hash = "sha256-...";
  };
  isLibrary = true;
  isExecutable = true;
  libraryHaskellDepends = [ base text ];
  executableHaskellDepends = [ base ];
  description = "...";
  license = lib.licenses.bsd3;
  mainProgram = "<exe>";
}
```

See [`pkgs/nixfmt`](pkgs/nixfmt/default.nix) and [`pkgs/cachix`](pkgs/cachix/default.nix) for working examples. `cabal2nix` output can be used as a starting point.

After a corepkgs pin bump, check whether anything in `pkgs/` now duplicates corepkgs:

```bash
nix-instantiate --eval --strict ci/shadowed-packages.nix -A all --json | jq .
```

## Validation

```bash
# Evaluate a package
nix-instantiate -A haskellPackages.<pkg>

# Build a package (or a top-level executable)
nix-build -A haskellPackages.<pkg>
nix-build -A <exe>

# CI eval gate: every hard system dependency reference in
# hackage-packages.nix resolves with corepkgs aliases disabled
bash ci/eval.sh

# CI regeneration gate: regenerating produces no diff
ci/check-regeneration.sh

# CI build smoke set (pkgs/, overrides/, a few key consumers); also run by eka-ci
nix-build ci/ci-jobs.nix
```

Nix evaluation warnings make `ci/eval.sh` fail. If it reports a missing name, corepkgs renamed or removed it — map it in `system-dependency-paths.yaml` and regenerate.

Packages that need a system dep missing from corepkgs are generated as `<name> = pkgs.<name> or null;` with `broken = !(pkgs ? <name>);`, so they become buildable automatically once corepkgs gains the dependency. Check whether such a dep exists in corepkgs under another name before accepting it.

## Regenerating

| Task | Command |
|------|---------|
| Update corepkgs pin and handle renamed attributes | [update-pins](.claude/skills/update-pins/SKILL.md) skill |
| Full Hackage update (snapshot bump → regenerate → fix fallout) or a single package bump | [update-packages](.claude/skills/update-packages/SKILL.md) skill |
| Bump the Hackage snapshot (`data/hackage/pin.json`) | `scripts/update-hackage.sh` |
| Regenerate `hackage-packages.nix` and `top-level.nix` from the pinned inputs | `scripts/regenerate-hackage-packages.sh` (`--hackage2ekapkgs PATH` builds the generator from a local checkout; `HACKAGE2EKAPKGS=BIN` uses a prebuilt binary) |
| Regenerate only `top-level.nix` | `scripts/generate-top-level.py` |
| Refresh `compiler.yaml` after changing `compiler.nix` | `scripts/generate-compiler-config.sh` |

After regenerating, re-run `bash ci/eval.sh` and `nix-build ci/ci-jobs.nix` — overrides may become obsolete or break with new versions.
